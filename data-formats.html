JSON Data Schemas

Taos Game Maker is powered by human-readable JSON formats. The schemas below illustrate representative structures used by the engine and the visual studio suite.

ℹ️
Illustrative Schemas: The examples below use mock dummy data to demonstrate schema conventions. Full, production-ready databases with hundreds of items, skills, and quests are included in the commercial release.

1. Enemy Combat Definition (enemies.json)

Defines monster stats, elemental resistances, turn priority, AI routine, and loot table.

Illustrative Enemy Schema (Truncated Sample) JSON 
{
  "id": "shadow_stalker",
  "name": { "en": "Shadow Stalker", "es": "Acechador Sombrío" },
  "level": 14,
  "stats": { "hp": 480, "mp": 120, "atk": 65, "def": 42, "spd": 28 },
  "affinities": { "fire": 1.5, "dark": -0.5, "light": 2.0 },
  "skills": ["slash_strike", "shadow_veil", "abyssal_drain"],
  "ai_pattern": "tactical_assassin",
  "drops": [{ "item": "shadow_essence", "rate": 0.4 }]
  ...
}

Key Properties:

  • id: Unique internal string identifier referenced across encounters and quest objectives.
  • name: Multi-language localized dictionary supporting instant runtime language toggling.
  • stats: Baseline numeric attributes driving the turn-based tactical combat formulas.
  • affinities: Elemental multipliers (>1.0 weak, <0.0 absorbed, 0.0 immune).
  • ai_pattern: Strategy key evaluated by the tactical turn decision tree.

2. Quest Tracking Definition (quests.json)

Manages multi-stage quest progression, objective completion tracking, and rewards.

Illustrative Quest Schema (Truncated Sample) JSON 
{
  "id": "quest_ancient_shrine",
  "title": { "en": "Secrets of the Shrine", "es": "Secretos del Santuario" },
  "category": "main",
  "recommended_level": 12,
  "steps": [
    { "id": "s1", "desc": "Explore the Sunken Vault", "target": "poi_vault_entrance" },
    { "id": "s2", "desc": "Defeat the Temple Sentinel", "target": "temple_sentinel", "count": 1 }
  ],
  "rewards": { "xp": 1200, "gold": 350, "items": ["relic_sun_stone"] }
  ...
}

Key Properties:

  • steps: Ordered array of quest milestones with visual journal progress indicators.
  • target: Entity ID (POI, enemy, or item) linked to automatic condition checks.
  • rewards: Granted automatically upon quest completion via the rewards subsystem.

3. Branching Dialogue Node (npcs/*.json)

Powers the Visual Novel dialogue tree with speaker portraits, expressions, and player choice branches.

Illustrative Dialogue Node (Truncated Sample) JSON 
{
  "node_id": "keeper_greeting",
  "speaker": "temple_keeper",
  "portrait": "keeper_mystic.png",
  "text": {
    "en": "The fractured barrier will not hold much longer, traveler.",
    "es": "La barrera fracturada no resistirá mucho más, viajero."
  },
  "condition": "gflag(\"met_elder\") and not gflag(\"barrier_cleared\")",
  "choices": [
    { "text": "I am ready to enter the dungeon.", "next": "enter_trial" },
    { "text": "Tell me more about the ancient sphere.", "next": "lore_inquiry" }
  ]
  ...
}

High-Level Trigger Evaluation

Dialogue nodes and quest triggers utilize a simple, secure condition evaluation syntax:

High-Level Condition Evaluation (Pseudocode) Logic 
if GlobalState.has_flag("met_elder") and Party.level >= 10:
    DialogueSystem.present_branch("enter_trial")
else:
    DialogueSystem.present_branch("fallback_warning")
...
