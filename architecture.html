System Design

Taos Game Maker Architecture

Taos Game Maker is engineered around a clean, decoupled three-tier architecture. It bridges human-readable JSON schemas, a visual web-based studio suite, and a high-performance Godot 4 client engine.

Tier 1: Pure Data-Driven Core

Unlike monolithic game projects where game balance, dialogues, and coordinates are hardcoded into engine scripts, Taos Game Maker stores 100% of game definitions in isolated JSON files:

  • data/world.json: Overworld grid coordinates, terrain codes, weather, and object placement.
  • data/dungeons/: Grid layouts, modular wall orientations, doors, chests, and boss spawn triggers.
  • data/enemies.json: Combat stats, elemental resistances, turn speeds, drops, and AI ability pools.
  • data/skills.json: Target scopes, MP/AP costs, status affliction chances, and visual FX keys.
  • data/npcs/: Branching dialogue trees, speaker portraits, choices, and condition evaluations.
  • data/quests.json: Objectives, step tracking, journal entries, and reward allocations.

Tier 2: The Local Web Studio Layer

The studio suite is hosted locally on your machine via a lightweight Python server (editor/serve.py). It exposes a rich, responsive interface with over 45 dedicated managers:

World & Dungeon Suite

Real-time map painting, terrain brush, entity placement, dungeon modular piece architect, and interactive 3D walkthrough simulator.

Narrative & Quest Suite

Node-based visual dialogue graph editor, VN asset previewer, NPC presence managers, and branching quest wizards.

Combat & Systems Suite

Turn-based sandbox simulator, skill synergy balancer, profession progression trees, and world transform event managers.

Validation & QA Suite

Automated data integrity validator that scans for broken IDs, missing assets, circular quest triggers, and orphan nodes.

Tier 3: Godot 4 Client Runtime Engine

The Godot 4 project is structured around modular Autoload singletons and isolated View controllers:

Core Engine Autoloads

  • Design Manager: Loads and caches JSON databases, provides unified accessor APIs, and hot-reloads data during development.
  • GlobalState: Manages runtime session data, party members, inventory, quest progress, story flags, and persistence.
  • SoundManager: Handles adaptive background music (BGM), environmental ambience, and spatial sound effects (SFX).
  • Juice: Centralized juice system delivering screen shake, chromatic aberration flashes, floating combat text, and haptic feedback.
  • Localization (i18n): High-performance multi-language lookup supporting dynamic runtime language swapping.

Engine View Subsystems

The gameplay transitions smoothly between specialized view controllers based on context:

View Controller Gameplay Mode Key Features
ViewWorld 3D Overworld Exploration Grid movement, biomes, dynamic camera, weather effects, POI triggers, transport vehicles.
ViewDungeon 1st-Person Dungeon Crawler 90° discrete grid turning, wall mesh instancing, torch lighting, chests, door locks.
ViewCombat Turn-Based Tactical Battle Timeline queue, active skill selection, status animations, floating combat numbers, enemy AI.
ViewDialogue / ViewPlace Visual Novel & City Exploration Character portraits, branching choices, city markets, craft workshops, quest journals.
ViewGather & ViewTransport Resource Gathering & Trade Farming nodes, resource processing, caravan transport routes, inventory management.

Extensibility & Modding

Because the engine is 100% decoupled from the data, you can create entirely new campaigns, standalone games, or mod expansions simply by swapping or editing the data/ folder.
